# PRD: Квалификационная анкета КП Documentolog / d8n.ai на официальном сайте

| Поле | Значение |
|---|---|
| **Версия** | 1.0 |
| **Дата** | 24.07.2026 |
| **Заказчик** | Documentolog Group · Sales / d8n |
| **Статус** | К постановке в разработку |
| **Референс** | Прототип `DG_anketa` (https://dg-anketa.vercel.app) |
| **Целевые сайты** | documentolog.com, d8n.ai (и/или поддомен) |

---

## 1. Цель продукта

Сделать на официальном сайте Documentolog / d8n.ai **официальный канал квалификации лида** для подготовки коммерческого предложения (КП):

1. Клиент заполняет структурированную анкету (или проходит диалог с ИИ с теми же полями).
2. Система определяет рекомендованный сегмент: **d8n SE** или **d8n AIE**.
3. Формируется готовый промпт / бриф для **d8n Sales** (генерация КП по стандартам компании).
4. Менеджер получает уведомление, данные сохраняются в CRM/CRM-like хранилище (Airtable или аналог), статусы сделки ведутся в дашборде.

**Бизнес-результат:** меньше ручного сбора данных, быстрее и качественнее КП, единый MEDDIC-контур квалификации, персональные ссылки менеджеров.

---

## 2. Проблема

Сейчас квалификация часто идёт через чаты, звонки и разрозненные формы. В итоге:

- не хватает полей для Pricing / Edition (N_full, deploy, EB, бюджет);
- d8n Sales запрашивает Missing Data;
- нет прозрачной привязки лида к менеджеру;
- нет единого статуса «Новое → КП → Договор».

Прототип `DG_anketa` уже закрывает этот сценарий. Нужно **перенести логику в официальный сайт** с корпоративным дизайном, безопасностью и поддержкой.

---

## 3. Пользователи и сценарии

### 3.1. Клиент (гость сайта)

- Заходит с лендинга / кнопки «Получить КП» / персональной ссылки менеджера `?mgr=...`.
- Заполняет анкету (5 шагов) **или** отвечает ИИ-ассистенту.
- Видит рекомендованный сегмент (SE / AIE).
- Получает подтверждение отправки.

### 3.2. Менеджер по продажам

- Раздаёт персональные ссылки.
- Получает email + запись в CRM.
- Копирует промпт в d8n Sales.
- Ведёт статусы в дашборде.

### 3.3. Руководитель продаж / админ

- Смотрит воронку по менеджерам.
- Настраивает список менеджеров, доступы, интеграции.

## 4. Варианты реализации (нужно выбрать или делать оба поэтапно)

| Вариант | Описание | Плюсы | Минусы |
|---|---|---|---|
| **A. Встроенная анкета** | Многошаговая форма на сайте (как прототип) | Предсказуемые поля, проще валидация и сегментация | Меньше «wow» |
| **B. Встроенный ИИ-ассистент** | Чат на сайте собирает те же поля диалогом | UX современный, выше engagement | Нужен жёсткий schema-output, сложнее контроль полноты |
| **C. Гибрид (рекомендуется)** | ИИ ведёт диалог, но заполняет ту же схему полей; в любой момент можно перейти в классическую форму | Лучший UX + те же интеграции | Больше объём работ |

**Рекомендация PRD:** MVP = **A (анкета)**, Phase 2 = **B/C (ИИ поверх той же схемы данных)**.

## 5. Объём MVP (Must Have)

### 5.1. Клиентская анкета (5 шагов)

#### Шаг 1 — Компания и контакт
- Наименование*, БИН/ИИН* (12 цифр)
- Вид собственности* (Частная / Государственная / Квазигосударственная)
- Отрасль*
- Холдинг (да/нет), кол-во ЮЛ
- Контакт: ФИО*, должность*, email*, телефон*
- Economic Buyer*, Champion (опционально)

**ФЛК (валидация):**
- Email: обязателен `@` и валидный формат (`name@domain.tld`)
- Телефон: только международный формат РК `+7` + 10 цифр, пример `+77011231212` (автонормализация ввода)
- БИН: ровно 12 цифр

#### Шаг 2 — Масштаб и боль
- N_full* (офисные пользователи СЭД), N_mobile
- Всего сотрудников, филиалы/города, рост штата
- Есть ли СЭД сейчас*, название/причина смены
- Цель внедрения*, боль*, видение на 12 мес.*, срочность

**Правило:** SE/AIE требуют **минимум 10** пользователей N_full (предупреждение; Business — другое подразделение, не считать в этом контуре).

#### Шаг 3 — Решение (модули и AI)
- BPM-модули* (без CRM — CRM не продаём)
- Коммуникации dg (mail / messenger / disk / mobile)
- AI-агенты (в т.ч. Executive — **для топ-руководства**)
- Потребность в custom AI

#### Шаг 4 — Техника
- Модель развёртывания*: SaaS / On-premise / **PaaS (гибрид)**
  - PaaS явно объясняется: платформа в облаке Documentolog, критичные данные/LLM/интеграции — во внутреннем контуре клиента
- GPU для локальной LLM
- Интеграции (1С, SAP, ЕСЭДО, AD/SSO, BI, самописные)
- Требования безопасности / локализация ПД

#### Шаг 5 — Коммерческие условия
- Срок договора*, аванс*, OPEX/CAPEX
- Статус бюджета*:
  - Согласован
  - В процессе согласования
  - **Предварительно (бюджета пока нет)** — вместо Speculative, с понятным пояснением
- Дедлайн сделки*, тендер ПГЗ
- Критерии выбора, комментарии
- Блок сравнения сегментов SE/AIE (опционально в MVP)

### 5.2. Сегментация (логика как в прототипе)

Считаются только **SE** и **AIE** (Business — вне scope этого продукта).

| Сигнал | Влияние |
|---|---|
| ≥1 AI-агент / custom AI | → **AIE** |
| Интеграции, расширенный BPM, dg-коммуникации, холдинг, On-prem/PaaS | усиливают **SE** (или AIE, если уже есть AI) |
| Нет AI-сигналов | → **SE** по умолчанию |

Клиент видит активный chip сегмента в процессе заполнения.

### 5.3. Персональные ссылки менеджеров

- URL вида `/kp-anketa?mgr=<manager_id>`
- Привязка заявки к менеджеру (имя + id)
- Email уведомления маршрутизируется на менеджера (маппинг в админке)

### 5.4. После отправки

1. Сохранение записи (CRM / Airtable / внутренняя БД).
2. Email менеджеру: краткая сводка + промпт для d8n Sales + вложение (md/pdf опционально).
3. Экран успеха клиенту.
4. Возможность «Скопировать промпт» (из письма — ссылка на защищённую страницу копирования; в письме JS не работает).

### 5.5. Дашборд менеджера (MVP)

- Авторизация (Basic Auth / SSO / корпоративный логин)
- Фильтр по менеджеру
- Статистика: всего / новые / КП отправлено / договоры
- Таблица заявок + смена статуса
- Просмотр/копирование промпта
- Генератор персональной ссылки

Статусы: `Новое` → `КП в работе` → `КП отправлено` → `Договор` / `Отказ`.

## 6. Phase 2 — Встроенный ИИ на сайте

### 6.1. Цель

Диалоговый ассистент на documentolog.com / d8n.ai собирает **ту же схему данных**, что и анкета, и на выходе выдаёт тот же payload + промпт.

### 6.2. Требования к ИИ

- System prompt + tool/schema: structured JSON по полям MVP.
- Нельзя завершать диалог, пока не собраны обязательные поля (или явный отказ клиента с пометкой).
- Те же ФЛК (email, телефон +7, БИН).
- Пояснения терминов (Economic Buyer, PaaS, N_full) — короткие, на русском.
- Кнопка «Перейти к классической форме» с переносом уже собранных ответов.
- Антиспам, rate limit, логирование диалогов (PII policy).

### 6.3. Что ИИ **не** делает в MVP Phase 2

- Не называет цены/ставки (ПП19 / Pricing — ставки не раскрывать клиенту).
- Не генерирует финальное КП клиенту (это делает менеджер через d8n Sales).
- Не обещает сроки внедрения без менеджера.

## 7. Данные и интеграции

### 7.1. Выходной артефакт (промпт d8n Sales)

Структура как в прототипе:

- Организация, масштаб, боль (MEDDIC), решение, техника, коммерция, стейкхолдеры
- Рекомендованный сегмент SE/AIE
- Инструкция: КП по стандарту L7.6 / Pricing L1.4 (внутренние версии уточнить у Sales Ops)
- Явно: «не запрашивай Missing Data, если поля заполнены»

### 7.2. Системы

| Система | Назначение | MVP |
|---|---|---|
| Официальный сайт (CMS/фронт) | UI анкеты / виджет ИИ | Да |
| Backend API | submit, rows, update status, prompt-by-id | Да |
| Email (Resend / корпоративный SMTP) | Уведомление менеджеру | Да |
| Airtable **или** внутренняя CRM/БД | Хранение заявок | Да (выбрать одну) |
| d8n Sales | Генерация КП из промпта | Ручной copy в MVP |
| Аналитика (GA/Metrika) | Воронка шагов | Желательно |

### 7.3. Безопасность

- Секреты только в env (никаких ключей в репозитории).
- Дашборд и API чтения заявок — только авторизованный доступ.
- CORS ограничен доменами компании.
- Rate limit на submit.
- Согласие на обработку ПДн (чекбокс + ссылка на политику).
- Логи без хранения полного промпта в публичных CDN.

## 8. UX / дизайн

- Бренд Documentolog / d8n: navy / blue / yellow, логотип, hero.
- Мобильная адаптация обязательна.
- Подсказки «?» у сложных полей (как в прототипе).
- Прогресс шагов + индикатор сегмента.
- Не показывать ложный «успех», если submit не прошёл.
- Язык: **русский** (MVP); казахский — Phase 3.

## 10. Критерии приёмки (Acceptance Criteria)

1. С `documentolog.com` (или согласованного URL) открывается анкета, визуально в брендбуке сайта.
2. Все обязательные поля валидируются; email и телефон по правилам ФЛК выше.
3. CRM отсутствует в списке модулей.
4. PaaS описан как гибрид (понятный текст для клиента).
5. Статус бюджета содержит «Предварительно…», без англ. Speculative в UI.
6. Executive-агент подписан «для топ-руководства».
7. Сегмент SE/AIE считается по правилам §5.2 и отображается клиенту.
8. `?mgr=` привязывает заявку к менеджеру и влияет на email.
9. После успешной отправки: запись в хранилище + письмо менеджеру с промптом.
10. Дашборд: список, фильтр, статусы, копирование промпта — только после авторизации.
11. При ошибке API клиент видит сообщение и может повторить отправку.
12. Нет секретов в клиентском коде.

## 11. Вне scope (не делать в этой задаче)

- Онлайн-оплата / e-commerce.
- Автопубликация КП клиенту без менеджера.
- Полный расчёт цены на сайте (ставки не раскрывать).
- Documentolog Business как основной сегмент этой анкеты.
- Мобильное native-приложение.

---

## 12. Метрики успеха

- % завершённых анкет от начавших (≥ 40% цель после стабилизации).
- Доля заявок с полным набором полей для d8n Sales без Missing Data (≥ 90%).
- Среднее время до первого КП менеджером (снижение vs baseline).
- Кол-во заявок через персональные ссылки менеджеров.

## 13. Этапы поставки

| Этап | Срок (оценка) | Результат |
|---|---|---|
| **Discovery + дизайн** | 1 нед. | Макеты в дизайн-системе сайта, утверждение полей |
| **MVP анкета + API + email + хранилище** | 2–3 нед. | Продакшен на поддомене/разделе сайта |
| **Дашборд менеджера** | 1–2 нед. | Статусы, фильтры, копирование промпта |
| **Hardening** | 1 нед. | Auth, rate limit, ПДн, мониторинг |
| **Phase 2: ИИ-виджет** | 2–4 нед. | Диалог → та же схема данных |

Оценки уточняются командой разработки после аудита текущего стека сайта.
